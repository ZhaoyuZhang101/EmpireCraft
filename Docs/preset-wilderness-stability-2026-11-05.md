# 预设剧本同一局内的区划稳定性

用户确认问题发生在同一局推进或读档后，并提供河西、甘州、青海附近的省界截图。截图本身不足以判断每次政治归属变化的来源；代码检查发现地理重划与自动行政改划都有可触发此现象的路径。

## 原因

- 读档仍重新归类、连片，再按重叠匹配旧区域。保存的外沿也被当作核心类型重新采样，存在外沿扩张、同类区域合并、拆片换编号和名字的可能。
- 村镇、厂区修订会定期要求全图重组，不只影响实际占用的那一块。
- 通用行政区整合、年度法理纠偏、迁回旧都后的行政重组，会把剧本省界改成通用法理的分区。
- `QueueAfterLoad` 中保存行政辖境的回调延迟查询 `_cities`，但 `Finish` 已把该临时城表清空。缺省补录又只覆盖有无人区锚点的城市，空表或部分表不能完整保护预设成员关系。
- 连通修补对别处缺失法理进行补挂时，吸收步骤仍可能改动已有有效承载城市的辖境。

## 修改

内置预设（`ForcesWild`）使用固定地理分区；玩家自定／随机世界保留动态分区规则。

1. 已存的无人区以原成员列表、编号、名字和文化为准。读档和普通刷新不重新切片；同类相邻区域也不自动合并。
2. 城镇、手动营建、实际开发只使占用的地块退出，其余部分仍沿用原地理身份。剩余部分小于首次建区的4块门槛时也不无故消失。局部改地形只处理变动的地块；新增山地、洪水、真实岩浆喷发仍能改变当地无人区。
3. 预设不因普通村镇／厂区修订发起年度全图重组。对已有有效承载城市、且完成过连通修补的辖境，补挂其他地块时保持原归属。城市实际改隶／战争易主仍由既有归属逻辑处理。
4. 停止预设的AI通用行政整合、年度法理纠偏，以及迁回旧都触发的全帝国改划。迁都本身继续执行。玩家仍可明确发动行政区重组。
5. 行政辖境保存改为提前捕获城市对象列表，回调执行时再记录这些城市最终的行政归属。旧档以修订号一次性补齐缺项，保留已有记录中的真实变化。
6. 预设的旧自动重划待办不再恢复执行。新主动发起的重组有单独的持久化标记，可以暂停、存读档后继续。旧档无法区分原任务由AI还是玩家发起，因此没有此标记的旧待办会停止；若玩家原先希望执行它，可重新主动发起。

## 存档与限制

更新重启后读取旧档即可沿用已保存的地理分区，不必为防漂移重新开局。不会把旧档的战争、已经发生的省份改隶或已成型行政机构强行回滚为史实开局；若要重新取得完整初始区划，需要新开对应剧本。地理分区固定不表示政治归属永久不变。

## 验证

- `check_preset_wilderness_layout.ps1`：25项生产方法检查，含连续50次强制刷新、5次存读档、相邻同类区不合并、局部营建／开发／洪水／岩浆、新地形、延迟捕获城表、AI改划入口、旧待办及主动重组恢复。
- `check_wilderness_administration.ps1`：39项，含旧档部分行政快照补录且不覆盖已有改隶记录。
- `check_wilderness_connectivity.ps1`：11项，含别处补挂不重分已有预设辖境。
- `check_wilderness_policies.ps1`：59项生产方法与10项JSON往返检查。
- 编译：0错误，15条既有警告。

以上为离线验证，尚未进入用户游戏目视验收。
