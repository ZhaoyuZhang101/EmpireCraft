# 剧本省界、飞地及明核心行政范围修复

本次由 Codex 直接修改实现。用户反馈临高1628剧本中关中、大同、中原等省辖境穿山、深入北方，西藏／青海附近有大量零散异色块，并提供明代两京十三布政司、巡抚分区等参考图。

## 原因与修改

1. **无人区分省不看地形。** `WorldMapZones.Partition(..., wild:true)` 原来按近似平地距离加随机起伏划分；运行时 `WildernessSystem.Roughness` 也只有随机代价。两处现在都包含实际地形阻力，保留原来要求的自然生长扰动。山脊、大漠与河谷不再全按平地处理。
2. **辅助治所可以独立长出飞地。** 每个州府点都作为独立零成本源，远处的同省治所可能隔着另一省长出一小块地。增加 `RootedPartition`：先保留与真实城市相连的推算部分，孤立提示块再从连通边界按地形接收。实际独立城市、明确手绘范围及历史面不当作无根提示删除。
3. **同法理不等于同一省。** 原连通检查允许一省借另一省同法理的城证明连通，随后仍画成远处那省。现在行政锚点连通同时核对实际归属国／省；修补时更新推算锚点，防止 `OriginOf` 下次查询恢复旧飞地。
4. **推算锚点压过其他政权的历史范围。** 未被明确历史面限定的行政锚点，不再越过另一政权已有的历史范围；同帝国内仍按行政锚点细分。编辑器笔刷、具体历史行政面优先于宽泛地理单元，永久中立保留。
5. **旧档修补入口被跳过。** 有效法理并不代表行政连通正确。世界地图存档新增 `boundary_revision`，旧档在首次挂接时额外进行一次连通核对，之后恢复已有快速路径。`bounded_anchors` 保存明确范围的保护标记，避免反复重算或改写手工划定的部分。
6. **明代核心没有历史行政面。** 原数据只有罗马117年的35份面，其余剧本主要依靠城市与治所推算。新增单独的 `administrative_boundaries_ming.json`：15个两京十三布政司级范围，按用户提供的明代行政／巡抚图作经纬度示意重建，共享边界，无重叠和内部缺面，保留海南岛。核心范围不会无限延伸到蒙古或青藏腹地。
7. **长城强行拆出“大同省”。** 已有明确行政面的山西不再因内外长城自动另设大同省；缺少范围的推算区仍保留原有隔墙分设。长城分地与军队通行规则继续适用。
8. **历史省名退回法理名。** 普通剧本行政区也保存 `admin_name/admin_empire`，在其所属帝国内沿用剧本的河南、陕西等名称，避免之后被法理名中原、关中替换。行政区真正独立后仍按既有独立国命名规则处理。

## 参考图和时代适用范围

- 用户指定的《明朝巡抚分区》及明代布政司图用于核心地理形态、治所与行政范围的核对；当前游戏模型仍以两京十三布政司级行政区承载，并未声称逐项实现每一巡抚的交叉辖权。
- 新增的面标为 `schematic-reference`，是参考图的示意重建，不是测绘级边界或声称取得了1628年的精密GIS数据。所有现有剧本列出的明行政区城市均位于对应范围。
- 临高剧本保持1628年的政权与城市设置，不把1433年的全幅政治疆域直接搬入，不扩大为对西藏、后金等政权的统一直辖主张。
- 共用地形／连通／命名修复对其他剧本也生效。唐、汉、春秋战国仍使用本时代的城市、治所、制度和名称；相同山河可作地理参照，不直接套用明省界。罗马原面数据未改动。
- 新面文件按 era、year、polity、division 严格匹配；复制临高的自定剧本可按已有 base 规则继承，自己明确画的边界优先。

可复现的数据生成：

```powershell
C:\Python312\python.exe Tools/WorldMap/ming_administration_source.py . --preview <输出路径.png>
```

生成器需要 shapely；预览另需 matplotlib。游戏运行仅读取JSON，不依赖这些Python库。生成器同时检查15区共享边界和全部已列明行政城市的落点。
